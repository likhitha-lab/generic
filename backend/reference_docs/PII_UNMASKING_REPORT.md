# PII Unmasking Layer — Implementation Report

Extended `app/services/pii_masker.py` (no new file, no architecture change — reused `unmask_text`/
`unmask_structured` exactly as they were). Not wired into `gemini_client.call_gemini` this round —
it still calls the plain `unmask_structured` as before (confirmed by grep). This round is scoped to
the restore/verification capability itself, per instruction; wiring the stronger variant into the
pipeline is a follow-up decision, not made here.

## What was added

- **`find_unknown_placeholders(text, mapping)`** — scans for anything shaped like a placeholder
  that isn't an exact, known value in the given mapping. Logs one warning naming the malformed
  token itself (never any original value). De-duplicated, order-preserving.
- **`validate_mapping_integrity(mapping)`** — never raises; returns a list of issue strings.
  Detects a **corrupted** entry (a value that isn't a well-formed placeholder at all — impossible
  from `build_mapping`, so finding one means the dict was altered afterward) and a **duplicate**
  (two different original values assigned the same placeholder — would make restoration
  ambiguous).
- **`unmask_text_verified(masked_text, mapping)`** / **`unmask_structured_verified(structured, mapping)`**
  — thin reporting wrappers around the existing restore functions. Return
  `{"text"/"structured", "unknown_placeholders", "mapping_issues"}`. Restoration behavior itself is
  completely unchanged — these call `unmask_text`/`unmask_structured` internally, never a
  different algorithm.

## Requirement-by-requirement

1. **Every valid placeholder replaced** — unchanged behavior, still `unmask_text`/`unmask_structured`.
2. **Verification:**
   - No placeholder remains for known ones — true by construction.
   - No incorrect replacement — only exact mapping values are ever restored; a malformed variant
     never resolves to the "closest" real value.
   - Repeated / nested / structured / list / dict restoration — all covered by dedicated tests
     (`test_repeated_placeholders_restore_correctly`, `test_nested_structures_restore_correctly`,
     `test_lists_restore_correctly`, `test_dictionaries_restore_correctly`).
3. **Malformed placeholders — detected, recorded, left unchanged, warned, never guessed:** all
   four named examples (`<CANDIDATE_NAME>`, `<CANDIDATE_NAME_01>`, `<CANDIDATE_NAME1>`,
   `<CANDIDATE_name_1>`) are individually tested — each is left byte-for-byte unchanged in the
   output and appears in `unknown_placeholders`, and `test_never_substitutes_the_wrong_value_for_a_malformed_placeholder`
   confirms none of them ever resolve to "Jane Doe" despite all four clearly being *attempts* at
   `<CANDIDATE_NAME_1>`.
4. **Mapping integrity — duplicate / missing / corrupted:** "corrupted" and "duplicate" are
   properties of the mapping dict itself (`validate_mapping_integrity`); "missing" — a placeholder
   present in text with no corresponding mapping entry — is really a property of *text + mapping
   together*, which is exactly what `find_unknown_placeholders` reports (documented explicitly in
   the function's own docstring rather than silently conflating the two).
5. **Never restore a placeholder not generated by this request** — structural, not a special case:
   `find_unknown_placeholders`/`unmask_text` only ever check against `set(mapping.values())` for
   the mapping *passed in* — a validly-shaped placeholder from a different request's mapping
   (`test_never_restores_a_placeholder_from_a_different_requests_mappings`) is correctly treated as
   unknown and left alone, since nothing here has access to any other request's state at all.
6. **Tests:** `tests/test_pii_unmasking.py`, 20 tests covering every category above — repeated,
   unknown, corrupted, nested, and mixed valid/invalid placeholders in one string.

## Design note: why a reporting layer, not a new restore algorithm

`unmask_text`/`unmask_structured` (used by `gemini_client.call_gemini` today) are untouched
on purpose — changing their actual restore behavior would be exactly the kind of architecture
change this task said not to make, and would risk the already-shipped, already-tested integration
from the previous round. The new functions are strictly additive: same inputs produce the same
restored output as before, plus a report of anything that couldn't be resolved and why.

## Not done this round (flagged, not decided)

`gemini_client.call_gemini` still calls plain `unmask_structured`, not `unmask_structured_verified`
— meaning a malformed placeholder in a real Gemini response (the residual risk flagged in
`PII_PIPELINE_INTEGRATION_REPORT.md`) would still silently survive into the final resume in
production today; the tools to detect and warn about it now exist, but aren't yet wired in. That's
a deliberate scope boundary for this round, not an oversight — wiring it in is a one-line change at
the single `call_gemini` call site whenever that's approved.
